# Web 面板与 Mini App

[← 返回 README](../README.md) · [文档目录](../README.md#-文档)

机器人在同一进程内嵌了一个零依赖的 Web 管理面板（`web_panel/`，aiohttp 托管），浏览器里就能完成 `/manage` 的全部管理工作，还能实时看到用户消息并直接回复。

## 功能一览

| 页面 | 能力 |
| :--- | :--- |
| 📊 仪表盘 | 用户 / 消息 / 黑名单 / 拦截篮统计，RSS、TG 监听、网页监控等定时任务的运行状态 |
| 💬 会话回复 | 左侧会话列表（可搜索）+ 右侧聊天记录，**新消息通过 WebSocket 实时推送**，输入框直接回复用户（回复会原样同步镜像到论坛话题），图片 / 视频 / 语音可在线预览；会话头部可**标为已读**（列表顶部有「全部已读」）、**暂停审查**（弹窗选时长）、**撤销 / 恢复验证**、封禁 / 解封；用户提交的「申请暂停审查」会以横幅显示，可直接批准或拒绝 |
| ⚙️ 配置中心 | `.env` 里配置项可视化修改：开关 / 数字 / 枚举 / 文本分控件呈现，密钥类只显示掩码；**绝大多数配置改完立即热生效**，少数结构性配置（群 ID、数据库路径等）标注「需重启」；面板密码通过独立表单更改；其它修改会持久化到数据库，重启后自动加载，也可一键还原为 `.env` 值 |
| 🤖 AI 设置 | 所有 AI 配置集中在这一页，分四个标签：**提供商与模型**（Gemini / OpenAI 兼容 / Claude 切换、API Key、Base URL 预设、按功能测试连接耗时、按用途选模型）；**功能开关**（AI 内容审查、自动回复、误杀申诉按钮、AI 自动撤销验证）；**生成参数**（按功能设置思考等级、最大输出 token、超时，输入 / 知识库截断，额外请求参数 JSON）；**提示词**（审查规则、出题规则、人格.md，可恢复默认）。全部热生效 |
| 💡 回复与关键词 | AI 自动回复总开关、可编辑并持久保存的 `人格.md`、知识库增删改查、关键词广告拦截开关与词表管理 |
| 👥 用户管理 | 全部用户、黑名单（手动拉黑 / 解封）、审查通行证（发放 / 取消）、暂停审查申请（批准 / 拒绝 / 取消）、拦截篮（查看 / 删除 / 清空）。顶部搜索框按 ID、昵称、用户名、备注和标签查找，全部用户标签还能搜消息内容和转发来源，并显示消息是谁发的、何时发的、是否被拦截。支持拦截放行、批量分组、一键收回验证或免审查，Mini App 同样可用 |
| 📣 广播群发 | 按全体用户、分组或标签发广播（后台异步投递，自动记录成功 / 失败），分组与成员管理（支持搜索多选），投递历史 |
| 📡 RSS / 监控 | RSS 订阅增删、口味关键词、授权用户、检查间隔；TG 群监听规则 CRUD 与最近发现的群聊；网页监控 CRUD（含 CSS 选择器高级配置）；补货监控；所有监控的命中记录和推送测试 |
| 🚀 更新部署 | 显示当前版本和最新版本，按部署方式提供一键更新；自动更新设置；Git 回滚和版本详情默认收起（操作均带二次确认） |
| 🛠️ 网络工具 | SSH 远程 Ping / NextTrace、服务器登记管理 |

## AI 模型与自动回复人格

- 进入「AI 设置」，点选协议卡片，填写 API Key、从「服务预设」里挑选服务地址（也可填自定义反代），点「测试连接」会先保存再发一条极短的测试消息，返回耗时与回复。点击「获取模型列表」即可把服务商当前可用的模型加入各用途输入框的候选项，也可以手动填写模型 ID。所有改动保存后立即生效；密钥同时出现在「配置中心 → AI 能力」，两边是同一份。
- 协议列表、预设地址与默认模型统一登记在 `services/ai_providers.py`，新增一种协议只需登记一项并在 `services/ai_service.py` 实现对应的 Provider。
- 在「回复与关键词」中编辑并保存 `人格.md`，可设定自动回复的称呼、语气和表达习惯，最多 20,000 个字符。内容保存在数据库，留空时使用默认人格；自定义人格只影响表达风格，知识库回答规则和未命中兜底文案仍由系统规则控制。

## 启用与访问

面板默认**开启**，默认端口 **18080**，**不需要提前在 .env 里设置密码**：

1. 启动机器人（源码运行或 Docker 拉起均可）
2. 浏览器打开 `http://127.0.0.1:18080`。远程 Docker 主机可先运行 `ssh -L 18080:127.0.0.1:18080 用户名@服务器地址`，再打开本机地址
3. 首次访问会进入**初始化页面**，设置一个登录密码（至少 8 位，只保存 SHA256 摘要）
4. 保存后自动登录，开始使用

```bash
# .env（全部可默认；密码建议走上面的网页初始化，也可在此预设）
WEB_PANEL_ENABLED=true
WEB_PANEL_HOST=127.0.0.1      # Docker 部署由 compose 注入 0.0.0.0，无需修改
WEB_PANEL_PORT=18080
WEB_PANEL_PASSWORD=           # 留空 = 使用网页初始化；也可在此预设
```

**Docker 部署开箱即用**：仓库自带的 `docker-compose.yml` 已将面板端口绑定到宿主机回环地址（`127.0.0.1:18080:18080`），容器内监听地址为 `0.0.0.0`。本机可直接访问；远程管理使用 SSH 隧道。若要通过反向代理提供远程访问，请先在 `.env` 预设强密码，再将代理连接到本机端口。如果改了 `.env` 里的 `WEB_PANEL_PORT`，记得把 compose 的映射同步修改。

> [!WARNING]
> 初始化窗口为 **15 分钟**，只限制首次设置密码。窗口关闭仍未设置密码时，面板会锁定；重启容器可重新进入初始化，或在 `.env` 预设 `WEB_PANEL_PASSWORD`。登录后可随时在「配置中心 → 修改面板密码」更改，不受该窗口限制。请不要把未设置密码的初始化页面开放给不可信网络。

> [!TIP]
> 更新部署流程：代码推送到 `main` 后 GitHub Actions 自动测试并构建 `latest` 镜像；推送 `v*` 版本 tag 还会构建同名版本镜像。服务器上 `git pull`（更新 compose）→ `docker compose pull && docker compose up -d` 即可。Watchtower 默认检查 `latest`；如需固定到某个版本，可设置 `UPDATE_IMAGE_TAG`。日常更新也可通过面板触发——端口映射与监听地址已随容器配置固化，重建后依然直接可访问。

## 安全机制（公网加固）

- **密码登录**：支持网页初始化设置（只存 SHA256 摘要）或 `.env` 配置（明文 `WEB_PANEL_PASSWORD` / 摘要 `WEB_PANEL_PASSWORD_SHA256`），HttpOnly + SameSite=Strict Cookie 会话，24 小时滑动过期
- **更改密码**：登录后通过配置中心的独立表单随时更改（需验证当前密码，新密码为 8–128 位）；密码以 SHA256 摘要写入数据库覆盖层，修改后撤销其它浏览器会话
- **登录限速**：同一 IP 连续失败 5 次锁定 15 分钟；经反向代理时开启 `WEB_PANEL_TRUST_PROXY=true` 以按 `X-Forwarded-For` 识别真实来源
- **CSRF 防护**：所有写操作必须携带自定义请求头，跨站表单无法伪造
- **安全响应头**：严格的 CSP、`X-Frame-Options: DENY`、`nosniff`、`no-referrer`
- **首次初始化窗口**：未设密码时面板进入 15 分钟初始化模式，窗口内除设置密码外所有接口拒绝访问；窗口关闭仍未设置则面板**整体锁定**（重启可重新初始化）。密码设置后可在登录态随时更改
- **审计日志**：所有改状态的面板操作都会记录到日志（敏感值不落日志）

> [!IMPORTANT]
> 远程部署请先在 `.env` 预设强密码，再通过 HTTPS 反向代理（Nginx / Caddy）提供访问，并按需开启 `WEB_PANEL_TRUST_PROXY=true`。不要把未设置密码的初始化页面开放给不可信网络。

## Telegram Mini App（Turnstile 验证与手机管理）

Mini App 挂在面板的 `/miniapp/` 路径下，和面板共用端口与反向代理，提供两个入口：

- **人机验证**：配好 Turnstile 后，`random` 和 `turnstile` 模式都先让新用户点按钮打开 Cloudflare Turnstile，通过后自动补发验证前的消息。验证出错或没通过时，机器人把普通验证题发到聊天；页面完全打不开时，60 秒后再发消息会出现换题按钮
- **手机管理页**：管理员点聊天框左下角的「管理面板」菜单按钮打开，也可以私聊机器人发 `/mobile`，免密码，包含概览、用户管理、配置中心、AI 设置、回复与关键词、广播与分组、RSS 与各类监控、更新部署和网络工具。这里不能回复用户，用户详情里的消息记录是只读的

启用步骤：

1. 确认面板已经能通过 HTTPS 域名访问。现有反向代理转发整个域名时不用改；只转发部分路径时要补上 `/miniapp/`
2. 在 Cloudflare 后台创建 Turnstile 组件，主机名填面板域名
3. 在 `.env` 里配置后重启：

```env
MINIAPP_PUBLIC_URL=https://panel.example.com/miniapp
TURNSTILE_SITE_KEY=<Site Key>
TURNSTILE_SECRET_KEY=<Secret Key>
VERIFICATION_MODE=turnstile
```

需要 `WEB_PANEL_ENABLED=true`。管理员要先和机器人对话过，重启后才能看到菜单按钮；普通用户不显示这个按钮，只有需要验证时才会收到验证按钮。Mini App 和面板登录页在同一个域名下，公网部署时要设置强密码并开启 `WEB_PANEL_TRUST_PROXY=true`。

安全边界：

- `/miniapp/api/` 下只注册 `web_panel/miniapp.py` 里 `ALLOWED_ROUTES` 列出的接口，密码登录、首次设密、修改面板密码和会话回复都不在这个路径下
- 手机管理页能改 API Key 和 Token、发广播、管理 SSH 服务器、更新机器人，权限与网页版接近。**Telegram 账号等于管理入口，请给 `ADMIN_IDS` 里的账号开启两步验证**
- 把自己移出 `ADMIN_IDS` 后会立即失去手机管理权限，需要回网页版恢复
- 经 Cloudflare 代理时，单次请求约 100 秒没有响应就会超时。NextTrace、安装工具这类耗时操作可能显示失败，但服务器上的任务仍在运行，以实际结果为准
- 身份来自 Telegram 签名的 `initData`，一小时内有效；只有 `ADMIN_IDS` 里的用户能拿到管理会话，且每次请求都会重新检查
- Turnstile 加载失败或校验服务不可用不计入验证失败次数

## 配置热生效的原理

Web 面板修改 `.env` 类配置时，会写入 SQLite 的 `settings` 表作为**覆盖层**（优先于 `.env`），并通过 `config.apply_override()` 直接更新运行中的配置。因此：

- 绝大多数配置（限速阈值、AI 密钥、验证参数等）改完立即生效，无需重启
- AI 密钥 / 反代地址变更会自动重建 AI 客户端
- 少数配置项（`MAX_MESSAGES_PER_MINUTE`、`BOT_TOKEN`、`FORUM_GROUP_ID`、`DATABASE_PATH`、`TG_API_*`、监听端口等）在界面上标注「需重启」，修改后重启容器/进程生效
- 覆盖值在重启后自动加载；在面板里点「还原」可回到 `.env` 原值

> RSS 开关 / 检查间隔、关键词拦截开关属于运行时设置（存于 RSS 状态文件或 `settings` 表），不走这套覆盖层，在各自页面修改即可。
